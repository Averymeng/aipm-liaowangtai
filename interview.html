① 一句话定位

AIPM·瞭望台 是一个面向 AI 产品决策者的智能研究与报告生成系统：你输入一个研究目标（产品分析 / 竞品对比 / 市场扫描 / 产品选型 / 机会探索），它实时联网检索，产出结构化、带证据来源、可视化的研究报告——把原本要花数小时的跨源调研，压缩成「一次提交 + 一份报告」。

领域限定：只做 AI 相关（大模型 / 对话 / 绘画视频 / 办公效率 / 营销 / 编程 / 搜索 / 公司·基建）。本质是「skill + 固定顺序流水线」，不是会自由发挥的 Agent。

② 2 分钟产品介绍（逐字稿结构）

开场（15 秒） 面试官好，我想讲一个我自己从 0 到 1 搭的 AI 产品项目——AIPM·瞭望台。它解决的是 AI 产品经理自己最痛的一件事：做竞品或选型调研时，信息散、来源杂、还容易凭印象下结论。 痛点（25 秒） AI 行业迭代极快，一个产品的定价、能力、口碑分散在官网、定价页、博客、GitHub、Reddit、新闻里。人工去搜、交叉验证，一份报告动辄几小时，而且结论常常没有出处、容易幻觉。 产品是什么（40 秒） 我做了一个输入「研究目标」就能出报告的系统。用户可以用自然语言说「分析一下 Cursor」，也可以直接点名「对比 Cursor 和 Dify」。系统会先解析意图——对象是谁、要比什么、限哪些维度；然后实时联网检索；最后按固定框架写出一份带「结论-来源」绑定的报告，并用 ECharts 渲染成能力雷达图、市场地图、时间线这些可视化图表。它有两类模式：对比模式只比用户点名的几个；竞品分析模式会给单主体自动补 5 个竞品再对比。 我的角色与做法（25 秒） 我既是产品设计也是实现者。我定了三条核心纪律：零确认直跑、证据可追溯、约定写法驱动可视化。尤其是「证据可追溯」——每条结论必须绑来源、分事实/洞察/建议，来源缺失就标「未查证」，绝不编造数据。这也是我作为 PM 对「可信 AI 产品」的理解。 边界与价值（15 秒） 它没有做数据库、RAG、多智能体——MVP 我刻意聚焦单条可验证闭环。它的价值是把「数小时调研」变成「一次提交」，结论还能溯源，能直接用于评审、立项和竞品跟踪。

③ 背景与痛点

  • 信息分散耗时：官网 / 博客 / 社区 / 新闻 / 代码仓库散落各处，人工搜集成本高。
  • 来源不可信：网络信息良莠不齐，结论常无出处，难以交叉验证。
  • 缺乏统一框架：不同人调研口径不一，结果不可比、难沉淀。
  • 产出非结构化：笔记/截图零散，无法直接用于汇报、评审、立项。

一句话：AI 行业快、散、虚，PM 做决策最缺的是「可信、可比、可复盘」的结构化情报。

④ 设计理念（三大核心纪律）

纪律一零确认直跑

解析完默认直接检索出报告，不弹确认卡打断。唯一例外：仅当「单对象且措辞无法判定是产品分析还是竞品分析」时，弹一个 A/B 轻询问。其余字段用合理默认值，报告顶部用一行「本次假设」明示口径，确认动作后置到看报告之后（可增量重跑，如「加 Trae」「只盯定价」）。

纪律二证据可追溯

每条重要结论绑定：结论、来源、时间、来源类型、可信度。结论分三类——事实（可核实客观信息）、洞察（基于事实的分析判断）、建议（面向决策的行动）。来源缺失标「未查证」，严禁编造。

纪律三约定写法 → 可视化

报告用固定约定写法（特定表格/标题结构）撰写，由渲染脚本生成图表页。写作者只遵守写法，不关心图表实现；要改视觉效果只动渲染器，不改内容。

取舍不为「显得高级」加复杂度

MVP 明确不做数据库 / RAG / LangGraph / 量化评测。复用成熟的自包含 ECharts 渲染器，网站化时只丢胶水代码。诚实优先：原型就是原型，不把「待验证」写成「已实现」。

⑤ 双模式与入口（5 类研究目标）

研究目标说明示例输入
产品分析系统分析单个产品分析一下可灵
竞品对比比较若干点名对象对比 Cursor 与 Dify
市场扫描盘点一条赛道AI 编程助手赛道有哪些玩家
产品选型按需求选工具小团队做 AI 客服选哪个
机会探索找空白与可切入方向AI 办公还有哪些空白

双模式

  • 对比模式：用户点名 N 个 → 仅就这 N 个正面对比，不引入外部竞品（如「Kimi 和豆包长文本谁强」，只比这俩，长文本维度高亮）。
  • 竞品分析模式：用户只给 1 个主体 → 先深析该主体，再对比默认 5 个竞品（候选初稿来自预置清单，确认后实时检索扩充），并含「机会点」模块。

输入支持自然语言（「分析一下可灵」）与结构化（直接填 1–3 个对象名）。

⑥ 10 维度分析框架

排序固定：用户体验位于商业模式与增长之间；风险与短板永远置末。维度无重叠，各看一个切面。

#维度看什么
1市场与定位目标用户、使用场景、品牌调性、赛道规模与位置
2产品与核心功能功能清单、核心场景覆盖、差异化功能点
3AI 能力底层模型、基准表现、生成质量、上下文长度、一致性、速度
4数据壁垒数据资产、数据飞轮、护城河、隐私与合规
5技术与生态技术架构、API 开放、第三方集成、开源与开发者生态
6商业模式与定价免费/订阅/按量/企业版、价格带、变现边界
7用户体验易用性、界面、延迟、稳定性、客服
8增长与运营获客渠道、内容打法、社区、口碑、病毒机制
9机会点竞品未覆盖的空白、真实需求、可切入方向（按意图可选）
10风险与短板合规风险、技术依赖、模式缺陷、竞争短板（置末）

评分口径：1–5 分制（5=领先，3=行业平均，1=基本不覆盖），在图表图例中轻量说明，不作免责声明。

⑦ 技术架构与流程

5 步流水线

  1. 意图解析：自然语言/结构化输入 → 对象（1–3）、目标类型、限定维度、模式。
  2. 研究简报：零确认直跑下，此步实为「看报告后确认」，报告顶部一行「本次假设」明示口径。
  3. 实时检索：按维度并行检索，每条结论带来源（官网/帮助文档/定价页/博客/发布说明/GitHub/Reddit/Product Hunt/Hacker News/新闻/财报）。不做持久化知识库、不做 RAG。
  4. 撰写报告：按 11 章节 + 约定写法写 Markdown，结论分事实/洞察/建议。
  5. 渲染：build_report.py 生成自包含 ECharts 可视化 HTML。

技术选型

  • 后端：Python + FastAPI，复用渲染器。
  • 外部依赖：DeepSeek（分析/撰写）+ Tavily（实时检索）。
  • 渲染：自包含 ECharts HTML，零外链，可直接打开/分享。
  • 预置竞品：preset-competitors.md 是静态种子表（非 RAG、非向量库），仅作竞品分析模式快速建议。

⑧ 我的角色与关键决策（AIPM 视角）

我做了什么

  • 从 0 定义产品定位与目标用户（AI PM 0–5 年为主）。
  • 设计 10 维度分析框架与 5 类研究目标入口。
  • 定三条核心纪律，尤其是「证据可追溯」约束 AI 不幻觉。
  • 设计双模式，平衡「用户想比谁就比谁」与「自动补竞品」。
  • 定可视化约定写法 + 奶黄橘黄视觉规范，落地渲染器。

关键取舍决策

  • 不做 RAG/数据库：MVP 聚焦单条可验证闭环，先证明价值。
  • 零确认直跑：用「看报告后确认 + 增量重跑」换体验流畅。
  • 结论三分类：事实/洞察/建议分离，让 PM 知道哪些是推断。
  • 渲染与内容解耦：约定写法让非工程师也能产出一致报告。

⑨ 难点与亮点

难点

  • 实时检索质量依赖模型与搜索能力 → 多源并行 + 交叉验证 + 来源优先级。
  • 信息时效性 → 报告标注数据时间，关键结论标来源时间。
  • 幻觉风险 → 证据纪律（结论-来源绑定、未查证标注）。

亮点

  • 证据可追溯：每条结论可溯源，从机制上抑制幻觉。
  • 结构化可视化：雷达/地图/时间线直接可用于评审。
  • 零外链自包含：报告是单文件 HTML，离线可看、易分享。
  • 诚实边界：原型即原型，对外表达不夸大。

⑩ 对外表达边界（诚实原则）

面试与简历都适用——超出证据边界的话一句都不要说：
  • 状态：写「原型 / 离线验证」，不写"上线系统"（网站在搭、未部署）。
  • 用户：写「面向…设计 / 用公开样本验证」，不写"服务了 N 位用户"（无真实用户记录）。
  • 指标：不写提升百分比；量化评测体系未建，相关能力标「待验证」。
  • 技术词：每个词（Workflow / 检索 / 渲染器）都要能答"解决哪个节点、为何不用更简单方法、怎么失败"——答不出就删。

⑪ 面试高频追问 Q&A

为什么不做 RAG / 数据库，不怕信息过时吗？
MVP 目标是先验证「单次研究闭环」这个核心价值，而不是堆技术复杂度。每次研究都实时联网检索，本身就不依赖历史库，所以 RAG 在 v1 是冗余。时效性问题我用「报告标注数据时间 + 关键结论标来源时间」解决，而不是预先灌库。等闭环跑顺了，v1.1 再评估是否需要持久化知识库。
"证据可追溯"具体怎么落地，怎么防止模型编造？
三条硬规则：①每条重要结论后必须附来源角标，报告末汇总来源卡片（官网/定价页/GitHub/Reddit 等）；②结论分事实/洞察/建议三类，让面试官和读者一眼区分"客观信息"和"我的推断"；③来源缺失或存疑时标「未查证」，宁可降级也绝不编功能、价格、份额、融资数字。这是产品纪律，也是我对"可信 AI"的理解。
用户只输入一个产品，你怎么决定对比哪 5 个竞品？
用一份静态种子表 preset-competitors（按品类取同类其余产品，默认上限 5，不足跨相邻品类补），但它只是"快速建议"，不是封闭列表。真实检索是开放联网的，远多于此表；如果主体不在种子表，就实时检索或轻问用户，不会硬塞不相关的厂商进去。
为什么是"零确认直跑"，不怕跑偏吗？
调研类任务的默认意图其实很清晰，反复确认反而打断心流。我用两道防线兜底：报告顶部一行「本次假设」明示本次运行口径（对象/维度/深度）；确认动作后置到看报告之后，支持增量重跑（如"加 Trae""只盯定价"）。唯一会轻问的情况是单对象且措辞真判定不了产品分析还是竞品分析。
这个产品和通用 AI 助手（如直接问 ChatGPT）区别在哪？
三个差异：①统一分析框架——不是零散答案，而是固定 10 维度 + 11 章节的结构化报告；②决策导向——结论分事实/洞察/建议，带证据，可直接用于评审立项；③可视化可复用——雷达图、市场地图能沉淀对比，而不是聊完即忘。本质是"有纪律的研究流水线"，不是"又一次性问答"。
你作为 PM，这个项目里最得意的一个决策是什么？
是"约定写法驱动可视化"：我让报告用固定 Markdown 表格/标题结构撰写，渲染器自动出图。这样非工程师也能产出视觉一致的报告，改版式只动渲染器不碰内容。它把"产品定义"和"工程实现"解耦，是性价比最高的一个设计决策。
下一步规划是什么？
把本地渲染器升级为正式产品站：前端输入研究目标 → 后端接 LLM+搜索 API 实时出报告，托管用 CloudStudio 全栈一体（代码仓仍在 GitHub）。但对外我只说"在做网站化"，不会说"已上线"——这是表达边界。
